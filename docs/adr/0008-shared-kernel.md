# ADR-0008. 공유 커널(shared)은 최소한으로 둔다

- 상태: 승인
- 날짜: 2026-09-24

## 맥락

여러 모듈이 같은 개념을 쓴다. 금액(`Money`)은 catalog와 order가, 에러 응답 형식과 페이지 조회는 모든 모듈이 쓴다.

선택지는 두 가지다.

- **모듈마다 따로 만든다**: 모듈이 완전히 독립적이다. 대신 같은 코드가 반복되고, 에러 응답 형식처럼 통일해야 하는 것이 모듈마다 달라질 수 있다.
- **공유 커널을 둔다**: 한 곳에서 관리한다. 대신 공유 커널이 바뀌면 모든 모듈이 영향을 받는다. MSA로 가면 공통 라이브러리가 되어 버전 관리 대상이 된다.

## 결정

`shared` 모듈을 두되, 들어갈 수 있는 것을 제한한다.

| 들어갈 수 있는 것 | 예 |
|---|---|
| 불변 값 객체 | `Money` |
| 예외 기반 타입 | `BusinessException`, `ErrorType` |
| 기술적 공통 기반 | `newId()`, `PageQuery`/`PageResult`, `GlobalExceptionHandler`, `Clock` 설정 |

| 들어갈 수 없는 것 |
|---|
| 비즈니스 규칙 (예: 할인 정책) |
| 특정 모듈의 개념 (예: `MemberId`) |
| 상태를 가진 서비스 |

- Modulith에서 `shared`는 `Type.OPEN` 모듈로 선언해 하위 패키지를 모두 공개한다.
- OPEN 모듈이라도 각 모듈의 `allowedDependencies`에 `"shared"`를 명시해야 한다. 명시하지 않으면 `ModularityTests`가 실패한다 (P1에서 확인).

## 결과

- 에러 응답 형식, 금액 계산, ID 생성이 모든 모듈에서 같다.
- 비용: 공유 커널을 바꾸면 모든 모듈에 영향이 간다. 그래서 규칙을 지키는 게 중요하다.
- MSA 전환 시 `shared`는 공통 라이브러리(jar)가 된다. `GlobalExceptionHandler`처럼 Spring에 의존하는 부분과 `Money`처럼 순수한 부분을 나눌지는 그때 결정한다.
