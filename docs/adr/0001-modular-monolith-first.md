# ADR-0001. 모듈러 모놀리식으로 시작한다

- 상태: 승인
- 날짜: 2026-09-24

## 맥락

이 프로젝트의 목표는 모놀리식 서비스를 MSA로 **점진적으로** 전환하면서 주의할 점을 직접 확인하는 것이다.

처음부터 MSA로 만들면 전환 과정 자체를 관찰할 수 없다. 반대로 경계 없이 뭉친 모놀리식에서 출발하면, 전환 과정에서 드러나는 문제가 "MSA라서 생기는 문제"인지 "애초에 설계가 나빠서 생기는 문제"인지 구분할 수 없다.

사례 조사([시리즈 #0](../posts/00-how-companies-design-monoliths.md))에서 확인한 공통 순서는 이렇다. 코드 안에서 경계를 먼저 만들고, 그 경계가 단단해진 다음 프로세스를 나눈다 (Fowler의 MonolithFirst, Shopify의 컴포넌트화).

## 결정

- 배포 단위 하나, DB 하나인 **모듈러 모놀리식**으로 시작한다.
- 모듈 경계는 Spring Modulith로 정의하고 테스트로 강제한다.
- **운영 가능한 수준**(보안, 관측성, CI, 성능 기준선)까지 만든 다음에 전환을 시작한다.

## 결과

- 전환 전후를 같은 기준으로 비교할 수 있다. 성능 기준선은 모놀리식 단계에서 측정한다.
- 전환 과정에서 드러나는 문제는 "설계를 잘해도 남는 문제"로 좁혀진다. 이 시리즈가 보여주려는 게 바로 그것이다.
- 비용: 모놀리식 단계에 쓰는 시간이 길어진다. 의도한 것이다.
